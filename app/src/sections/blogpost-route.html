Why cPanel Served My Vite Build as a 404

Posted 12 July 2026

The build was fine. npm run build produced a dist/ that worked locally under vite preview, the zip uploaded cleanly, and cPanel’s Extract finished without complaint — then every asset came back 404. Not a blank page, not a broken import: a plain, confident 404 from LiteSpeed on files that were visibly sitting in the file manager.

The cause was permissions, and it started one layer below the project. The workspace lives on an SMB volume that forces mode 0700 on everything it writes. dist/ inherited it, the zip preserved it, Extract restored it faithfully, and LiteSpeed — running as a different user — could not read a single file. A web server that cannot open a file it can see reports exactly what it reports for a file that does not exist.

If a deploy fails identically on every file, stop reading your build config and start reading your file modes.

The fix belongs in the build, not in a checklist taped to the monitor. A small packaging script runs as an npm postbuild hook: it walks the freshly built dist/, normalises the modes, and zips the result. Every build now emits an upload-ready dist.zip whose permissions survive the round trip.

  • Directories 755, files 644 — set at package time, not after upload.
  • The zip is the artifact; never upload a folder the SMB mount has touched.
  • One shared script, wired into every project in the workspace.

The general lesson: when a deployment target faithfully preserves metadata you never chose, normalise it at the last step you control.
